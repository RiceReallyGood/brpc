DECISION: lite-point-set = NOT_REQUIRED

# Phase 0 — 打点成本 microbenchmark 结果

Probe: `tools/latency_trace/probe/stamp_cost_probe.cpp`（standalone，无 brpc 依赖）。
`N = 2,000,000` 次迭代／组，四组测量：计数器频率标定、`clock_cycles()` 单读、
`clock_gettime(CLOCK_MONOTONIC)`（`cpuwide_time_ns()` 在 `WITH_CPU_FREQUENCY=0`
默认构建下的退化路径）、以及 `LT_STAMP` 等价物（读计数器 + generation 校验 + 一次
`store`）。每台机器跑 5 次，取值范围如下（未做任何取舍性挑选）。

## 0. 本机验证（x86_64 WSL，仅验证程序正确性，数字不计入结论）

```
counter freq (empirical) = 2496.067 MHz
counter freq (CNTFRQ_EL0) = 0.000 MHz  (n/a on this arch)
counter resolution = 0.40 ns/tick
clock_cycles()            = 7.70 ns/op
clock_gettime(MONOTONIC)  = 17.12 ns/op
LT_STAMP equivalent       = 8.37 ns/op
=> 36 points cost         = 301.33 ns (0.301 us)
sink=16216311171097286559
```

程序无崩溃，四组数字均在合理量级（无 <1ns 的反常低值），`sink` 非零且被打印，
说明编译器未把测量循环当死代码优化掉。`CNTFRQ_EL0` 一栏按预期显示
`(n/a on this arch)`（x86_64 无此寄存器，`clock_cycles()` 走 `rdtsc` 路径）。
程序判定：**正确，可送 aarch64 机器**。

## 1. 计数器频率标定（两台机器）

| 机器 | g++ | 核数 | load avg（跑测时） | 经验频率 | CNTFRQ_EL0 | 与 CNTFRQ_EL0 偏差 |
|---|---|---|---|---|---|---|
| suzhou950 | 12.3.1 (openEuler 24.03) | 384 | 1.04, 1.28, 1.51 | 100.001 MHz | 100.000 MHz | +0.0012% ~ +0.0014% |
| suzhou920B | 10.3.1 (openEuler 22.03) | 160 | 0.87, 0.50, 0.48 | 99.994 MHz | 100.000 MHz | −0.0055% ~ −0.0059% |

5 次运行内，每台机器的经验频率本身**完全稳定**（950 恒为 100.001 MHz，920B 恒为
99.994 MHz），说明该 200ms 采样窗口对频率标定是可靠的，不是单次运行的噪声。

**两台机器之间的经验频率互相比对**：
`|100.001 − 99.994| / 100.000 = 0.007%`，远低于 spec §8.1 规定的 0.1% 告警阈值。
**结论：两台机器的计数器频率一致（经验值同标称 100 MHz 相符，互相偏差
0.007% < 0.1%）**。`BogoMIPS: 200.00` → `CNTFRQ_EL0 = 100 MHz`（10ns/tick）的假设
得到实测验证，D1 公式 `L = RTT − S` 所依赖的「两台机器时钟频率基本一致」前提成立。
即便如此，`merge.py` 仍应按 spec 要求使用每台机器**各自**标定出的频率做换算，
不应假设两台完全相同后共用一个常数——这里的一致只是「验证通过」，不是「可以合并成
一个全局频率」的理由。

## 2. 四组 ns/op（各机器 5 次运行的范围）

| 机器 | `clock_cycles()` | `clock_gettime(MONOTONIC)` | `LT_STAMP` 等价物 | 36 点总开销 |
|---|---|---|---|---|
| suzhou950 | 6.16 ~ 6.17 ns/op | 23.16 ~ 23.37 ns/op | 7.09 ~ 7.19 ns/op | 255.15 ~ 258.70 ns（0.255~0.259 μs） |
| suzhou920B | 5.18 ns/op（恒定） | 23.18 ~ 23.25 ns/op | 5.87 ~ 5.90 ns/op | 211.22 ~ 212.26 ns（0.211~0.212 μs） |

**运行间抖动**：两台机器每组指标的 5 次运行差值都在 ±1.5% 以内（950 的
`LT_STAMP` 等价物 7.09~7.19 ns/op，跨度约 1.4%；920B 的对应跨度约 0.5%），
远小于「36 点开销是否超过 10% RDMA 时延」这一判据所需要的分辨力。两台机器都是
共享多核机器（384 核 / 160 核），跑测时 load average 均显著低于核数（950 约
1.0~1.5 / 384，920B 约 0.5~0.9 / 160），未观察到明显的邻居噪声或频率漂移；本次
测得的抖动幅度不足以改变下面的结论方向。

`clock_gettime(CLOCK_MONOTONIC)` 比 `clock_cycles()` 贵 3.6~4.5 倍（950: 23.2ns
vs 6.17ns；920B: 23.2ns vs 5.18ns），印证了 spec §8.1 的判断：在
`WITH_CPU_FREQUENCY=0` 的默认构建下，`butil::cpuwide_time_ns()` 退化为
`clock_gettime(MONOTONIC)` 的 vDSO 调用，比直接读 `cntvct_el0` 贵得多——这也是
`latency_trace` 选择直接调用 `clock_cycles()` 而非 `cpuwide_time_ns()` 的实测依据。

注意 920B 的每 op 成本反而低于 950（`LT_STAMP` 等价物 5.87ns vs 7.15ns
平均），尽管 920B 是核数更少、操作系统版本更旧的机器；这与"384 核 = 更快"的
直觉相反，说明两台机器单核微架构/主频不同，属于正常的机型差异，不影响本次结论
（两台机器的开销都远低于阈值，见下）。

## 3. 判据与结论（Step 4）

**判据**（来自 brief）：若 36 点总开销 > RDMA 端到端时延（5~15 μs）的 10%，
即超过约 0.5~1.5 μs，则必须实现 `lite` 点位集（spec §8.1，约 12 点，追加
Task 14）；否则 `-latency_trace_point_set` 这个 gflag 整体不实现，从 spec §8.1
的表中删去。

**实测的 36 点总开销**：

- suzhou950（12.3.1，更保守/更差的一台）：**0.255 ~ 0.259 μs**
- suzhou920B（10.3.1）：**0.211 ~ 0.212 μs**

取两台中较差（更高）的 950 数值 0.259 μs 作为上界，与判据的两端分别比较：

```
0.259 μs / 0.5 μs (10% of 5 μs 下界)  = 51.8%  → 36 点开销 = RDMA 下界端到端时延的 5.18%
0.259 μs / 1.5 μs (10% of 15 μs 上界) = 17.3%  → 36 点开销 = RDMA 上界端到端时延的 1.73%
```

即便取 RDMA 时延区间的**下界**（5 μs，对打点开销最不利的情形），36 点总开销也
只占端到端时延的约 **5.2%**，只有 10% 判据阈值的一半；取上界（15 μs）则仅占约
**1.7%**。两台机器、五次重复运行得到的数字都远低于阈值，不存在「跑一次刚好卡在
边界」的情况，也没有出现过任何一次运行落在阈值附近——离边界还有 2~5.8 倍的余量，
不属于需要谨慎表态的边界情形。

**结论：36 点全量打点方案在 RDMA 场景下的开销（约 0.21~0.26 μs）远低于
5~15 μs 端到端时延的 10%（0.5~1.5 μs）阈值，`lite` 点位集不是必需的。**

对应决策：**不追加 Task 14**；spec §8.1 表中的 `-latency_trace_point_set` gflag
整体不实现，应从 spec §8.1 的 flags 表中删去（`full`/`lite` 二选一的设计简化为
只有 `full`，即恒定 36 点）。

## 4. 两个已排查的干扰因素

1. **死代码消除（DCE）**：probe 把每组测量的读数都累加进 `sink` 并在末尾打印，
   四台机器 × 全部运行中都未出现异常低的 ns/op（例如 <1ns），`sink` 也均为非零
   的大数，说明测量循环没有被优化掉。
2. **频率漂移 / 噪声邻居**：两台共享机器（384 核 / 160 核）在跑测时 load average
   都明显低于核数；每台机器 5 次重复运行的四组指标波动都在 ±1.5% 以内，且频率
   标定值在 5 次运行中完全恒定，未观察到宽幅抖动。抖动幅度远不足以改变上面第 3
   节的判断方向。
